# Android gallery scale measurement

For functional checks, build the Android emulator APK with `pnpm android:build:emulator:agent`. Native image-processing performance must use the normal optimized release profile: run `node scripts/prepareAndroidGenerated.mjs x86_64`, then `pnpm exec tauri android build --apk --target x86_64 --ci --config src-tauri/tauri.agent.conf.json -- --locked`. Sign an installable verification copy using the same certificate as the synthetic profile, without changing product release signing settings. Record the build profile and installed APK hash. Install only on a disposable synthetic AVD after sustained ADB health checks. Open the initialized app and accept its own terms in that synthetic profile.

The runner requires explicit `--serial=emulator-...`, `--avd=...`, `--adb-port=...` and `ANDROID_HOME` (or `--adb=...`). It verifies the AVD name before connecting to the app. It uses the existing CDP helper, which blocks Realm and the translator preset endpoint.

Use `--action=memory` after app startup to verify positive app/renderer memory readings and candidate attribution without warming the gallery metadata index. This is a preflight receipt, not a timing result.

Run each action with those same target arguments:

1. `node benchmarks/gallery/android-scale.mjs --action=seed-images --pool=512 --dimension=2048`
2. `node benchmarks/gallery/android-scale.mjs --action=seed-aliases --count=10000 --assets=5000`
3. `node benchmarks/gallery/android-scale.mjs --action=metadata --count=10000`
4. `node benchmarks/gallery/android-scale.mjs --action=archive-fixture`
5. `node benchmarks/gallery/android-scale.mjs --action=scan --count=10000`
6. `node benchmarks/gallery/android-scale.mjs --action=seed-aliases --count=100000 --assets=5000`
7. `node benchmarks/gallery/android-scale.mjs --action=metadata --count=100000`
8. `node benchmarks/gallery/android-scale.mjs --action=archive-fixture`
9. `node benchmarks/gallery/android-scale.mjs --action=scan --count=100000`
10. `node benchmarks/gallery/android-scale.mjs --action=scan --count=100000 --cancel=true`

Seeding replaces the app's active database with synthetic data. Image bodies are generated through Canvas, stored through public CAS commands, and shared cyclically by aliases. The receipt records the actual unique body count. The character asset manifest is encoded by the product codec.

Restart the synthetic app after seeding. Open RisuNest settings, then Chat attachments. Run `--action=scroll --count=100000 --label=attachments`. Then open Synthetic Gallery's existing Additional Assets table, use its gallery button, and run `--action=scroll --count=5000 --label=assets` through the final item. Record the gallery cell count separately from the background table's input, preview, and total DOM counts, and retain the entry memory baseline. This exercises gallery scrolling while the existing table remains mounted. For a separate comparison of the gallery alone, open it from the character's icon section and switch to additional assets inside the overlay; use a different result label and preserve both runs. An isolated comparison does not replace the full traversal from the table entry.

The scroll action advances by 80% of the viewport, waits for every visible media region to finish loading an image with nonzero natural dimensions (a card-border sliver outside the media region is not a visible image), then waits through two animation frames, and checks that consecutive mounted windows cover every index through the final item. It records bounded histograms of `requestAnimationFrame` callback intervals (`rafInterval*` fields), long-task aggregates, DOM bounds, and app/renderer PSS and RSS samples. RAF callback intervals describe main-thread scheduling and are not displayed FPS. If a separate diagnostic captures compositor `DrawFrame` events, those events also do not prove completed presentation. Do not derive a display drop rate by dividing partially dropped-frame events by another event count. Assess actual touch scrolling and visible output alongside these diagnostics. `dumpsys meminfo --local` collects memory without asking the sandboxed renderer to run its Java dump handler. Missing or zero memory fields and absence of a sandboxed renderer fail the run. Each sample records candidate process names and count; renderer memory is explicitly the aggregate of all WebView sandboxed processes on the synthetic AVD when multiple candidates exist. The runner follows normal browser image loading and painting without calling `HTMLImageElement.decode()`; the browser controls decoding for display. Preserve visible gallery screenshots at intermediate checkpoints alongside the load-failure counts. At most three failed-window snapshots record bounded cell states, media geometry, source URLs, and recent resource timings before the runner stops. The default minimum dwell is 50 ms and can be set with `--dwell=...`.

For a cold native-preview run, force-stop the synthetic app and clear only its verified `AppPaths.cache/native-media/gallery-v1` directory. Preserve the original CAS and database, and record the exact removed cache path and file count. Restart the app before opening the gallery. Do not reuse derivatives generated by an earlier run as cold evidence.

For native-preview acceptance, add `--require-previews=true` to each scroll command. Every loaded visible image must then have natural dimensions at most 512 pixels and a source URL with `thumbnail=gallery-v1`; an original-image fallback fails the run. The receipt records verified windows and the maximum preview dimension. Separately open the viewer and download a small selection to verify that those paths still return the original dimensions and hashes.

Results go to `.tmp/gallery-scale` unless `--output=...` is supplied. Metadata results separate the first query for each sort from 24 later pages. Run timing measurements without competing builds or test workers. On Windows the runner records host memory, compiler processes, native test binaries, Cargo test commands, and known Vitest/tinypool/Node test workers (excluding its own process), and rejects a sample if a competing worker is observed or available host commit falls below 2 GiB. Emulator process CPU totals and private memory are also recorded. Before timing, identify the owned AVD and record other resident emulators. CPU growth alone does not establish a competing test; use host CPU headroom and an app idle-frame control to distinguish contention. Defer timing when a known competing test is active or the idle control is unstable, and disclose resident emulators in the environment receipt. Report emulator and fixture details with the results; these measurements do not establish physical-device performance.

The fixture also scales message text with the attachment count: 100 or 1000 scan characters, each with one conversation and 100 ASCII messages of 512 bytes. Receipts record exact character, conversation, message, and text-byte counts. Two extra characters provide live and archived-only location cases. Archive and scan commands above exercise the archived-only references and cancellation. Scan receipts include progress, total time, terminal state, and known-key locations. Measure metadata before scanning or opening the gallery so the first page starts with an unprimed metadata index.
